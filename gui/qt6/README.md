# ЕОМ «Київ» — Qt 6 Widgets GUI — tracked v1

**Призначення:** перший desktop GUI для демонстрацій, із постійним C++ CPU backend. Структура пультів плануватиметься за напрацюваннями Qt5 (2022) у `ucu-computer-science/Kyiv_emulator`, гілка `web`; старий код і старий емулятор **не переносилися**.

**v1r1:** додано обов’язкове `#include <QMainWindow>` у Qt frontend. У v1 відсутність цього заголовка спричиняла низку каскадних помилок компіляції, зокрема `expected class-name before '{' token`. Backend і протокол не змінено.

## Збирання та запуск (MSYS2 MINGW64)

Ця версія знаходиться у tracked-каталозі `gui/qt6/` репозиторію.
Всі виконувані файли, об'єктні файли та smoke-логи створюються виключно в `tempkyiv/qt6_build/`.

З кореня репозиторію:

```bash
bash gui/qt6/run.sh --smoke-only && bash gui/qt6/run.sh --reuse-build
```

Збирання потребує `mingw-w64-x86_64-qt6-base`, g++ та pkg-config.
`Qt6Widgets` уже кваліфіковано в MSYS2 MINGW64 з Qt 6.11.1.
Python, Qt Designer, QML і CMake не потрібні для цієї версії.

Команда `--smoke-only` перевіряє реальний backend без GUI-вікна;
`--reuse-build` запускає вікно без повторного збирання.

## Наявні функції

- **Постійний стан процесора:** завантаження `.k41` в RAM; Пуск / Пауза / Крок / Перезавантажити; F5/F6/F7, змінні темп і кількість команд у пакеті (до 32).
- **Індикатори:** регістри `C`, `K`, `A`, `P`, `Ц`, `T`, кількість виконаних команд. 41-бітове слово `K` та менші регістри як окремі лампи. Це функціональна візуалізація, не точна реконструкція історичного пульта.
- **Пам'ять:** вісімкові адреси, 41-бітові слова, перегляд по 32 слова, оновлення після кроків, після зупинки та періодично під час Пуску.
- **Трасування:** адреси виконаних команд. Обмежене останніми 1200 записами, щоб не витрачати пам'ять необмежено.
- **НК:** `3000–3002`, слово з пульта та повернення джерела «шафа».
- **Checkpoint:** зберегти / відновити стан у поточному backend-процесі, без запису на диск. Після закриття вікна checkpoint втрачається.
- **Швидкі приклади:** H9 (з `0143`) та H23 (з `0302`). Це короткі фрагменти для керованого покрокового показу. Не заявляється проходження всього історичного тесту.

## Архітектура

```text
Qt 6 Widgets, qt_main.cpp (не модифікує ядро)
            |
            | QProcess: асинхронні команди, один запит — одна відповідь
            v
kyiv_gui_backend.cpp (постійний C++ процес)
            |
            v
поточні src/main.cpp + src/asm_disasm.cpp (production CPU)
```

Backend без змін скопійовано з кваліфікованого Tkinter-прототипу GUI v1 (`fc073281...` SHA256). Відображення й виконання незалежні: Qt не зберігає `QWidget` усередині `Kyiv_t`. Запити з вікна асинхронні, GUI не виконує блокувальних циклів CPU.

Майбутній напрям: виділення CPU в окрему C++ бібліотеку, а потім пряме приєднання Qt через стабільний `EmulatorController` API. Після цього два процеси будуть об'єднані, протокол лишиться корисним для автоматичних тестів.

## Обмеження

- Не підтримуються файл checkpoint-а, підключений магнітний барабан, редактор пам'яті, графічні перфокарти/друк та асемблер у Qt GUI. Поточний backend не дозволяє виконання довільних команд із панелі без коду в RAM.
- Пауза діє **між пакетами**, максимум через 32 команди. `Run` у випадку діагностичної петлі не завершиться автоматично: використайте «Пауза».
- Дані історичних тестів мають свої початкові умови, а історична поведінка H10/H14/H17 залишається відкритою. Відображення їхніх поточних результатів не означає кваліфікації на реальній машині.
- Джерела старого Qt5-інтерфейсу — лише референс. Відтворення вигляду й топології ламп — наступний етап, після перевірки функціональних блоків.
- Перша Qt6-версія v1r1 успішно зібралася й пройшла native smoke у MSYS2 MINGW64 28.10.2026. Переміщений tracked-runner вимагає повторного короткого smoke перед Git-комітом.

## Діагностика

Маркер успішної перевірки після збирання:

```
QTGUI_BUILD=PASS; FRONTEND=QT6_WIDGETS; BACKEND=PERSISTENT_CPP; TRACKED_FILES=UNCHANGED
QTGUI_NATIVE_SMOKE=PASS; ROM=PINNED; H9=SOURCE_MATCH; CHECKPOINT_REPLAY=EQUIVALENT; PROTOCOL=1
```

Якщо компілятор повідомляє `Qt6Widgets not found`, перевірте, що активне саме **MSYS2 MINGW64** і команда `pkg-config --modversion Qt6Widgets` працює. Пакет `qt6-base` містить `Qt6Widgets`, `QProcess` та всі використані модулі Qt.
