# Функціональний FP-ROM ЕОМ «Київ» (H115-B20)

**Сучасна, обмежено перевірена реконструкція, НЕ історичний образ ПЗП.** Машинна реалізація операцій із рухомою комою описана у В. М. Глушкова та К. Л. Ющенко, *«Вычислительная машина „Киев“»* (1962), друк. с. 111–118. Канонічний 251-слівний лістинг зберігається **без жодних змін** у `../historical/gy1962/rom_modules/fp_simulation_251_printed.k41`. Цей каталог містить придатний для запуску, але синтетично виправлений варіант.

## Що містить приклад

- `inputs/FP_FUNCTIONAL_1962_RECONSTRUCTED.k41` — цілісний образ ПЗП для програмної МП, **257 машинних слів**. Завантажується як є; додаткових HOST-патчів під час виконання не потрібно.
- `PATCHES.json` — побітово точний перелік **12 відмінностей**: шість замінених надрукованих слів і шість синтетичних, **не надрукованих** у книзі слів. Тут є посилання на діагностичні етапи B8, B11, B12C та B19.
- `PROVENANCE.json` — контрольні суми вихідного й функціонального образів, обмеження та версії CPU.
- `native_rk4.cpp`, `native_regression.cpp` — runner продукційного CPU, адаптовані з H115-B19: завантажують **цілісний FP-ROM**; не містять адресних `write_rom` для внесення виправлень після завантаження.
- `reference/RK4_ORIGINAL_B16.k41` — саме та первісна FP-програма RK4 (без компенсаційного накопичення), що дала HOLD до B19 і PASS після B19. Вона не є історичним fixed-point RK4.
- `evidence/H115_B19_FP_SIGNED_OVERFLOW_NATIVE_EVIDENCE_V1.zip` — прийняте нативне свідчення: 51 арифметичний сценарій, 42/42 контрольні точки первісної RK4, 52 сесії CPU.
- `run.py`, `tests/` — офлайновий контроль і **нове** нативне виконання образу B20 із побайтовим порівнянням із B19.

## Чотири незалежні виправлення

| Етап | Адреси (вісімкові) | Сенс |
|---|---|---|
| B8 | `3467`, `3470`, `3474` | Дві маски мантис/порядків та команда додавання порядку |
| B11 | `3476`, **`3706–3707`** | Машинне порівняння мантис перед діленням, без HOST-зміни PC |
| B12C | `3455` | Перехід через процедуру округлення `3370` |
| B19 | `3367`, **`3710–3713`** | Розгалуження за знаком переповнення та корекція ±1/2 |

**Жирні адреси — шість сучасних синтетичних слів; первісне ПЗП їх не містить.** Зокрема, `3574` залишається невідомою й **не додана** до функціонального образу. Джерелом істини для повних 14-значних слів є `PATCHES.json`, а не ця таблиця.

## Спробувати та перевірити

З кореня Git checkout (Python 3.10+, а для нативного запуску — `g++` у MSYS2 MINGW64):

```sh
python -B examples/fp_rom_reconstructed/run.py --offline --repo .
python -B -m unittest discover -s examples/fp_rom_reconstructed/tests -p 'test_*.py' -v
python -B examples/fp_rom_reconstructed/run.py --native --repo . --out tempkyiv/B20_FP_ROM_NATIVE_REPLAY_01
```

`--offline` не запускає CPU: перевіряє канонічні входи, 257-слівний образ, кожну зміну та вміст збереженого B19 evidence. `--native` будує **незмінний продукційний CPU**, виконує 51 арифметичний сценарій і первісну RK4, а потім вимагає побайтового збігу **семи TSV** із B19. Результат та повні нативні траси зберігаються у новій директорії й ZIP поряд із нею. Якщо вказаний шлях уже зайнятий, запуск fail-closed (без перезапису). При невдачі у фазі виконання створюється evidence зі статусом HOLD.

Образ `KYIV41-OCT1` — сучасний контейнер слів, а не історичне кодування перфокарт чи фізичне ПЗП. Машинна МП виконує робочі команди через диспетчер `3300` з вибором програми у другому адресному полі НК `3000`; верифікована траса використовує лише machine-code керування після початкового старту. Для довільної FP-програми початковий стан та допустимі адреси необхідно перевіряти окремо, не припускати загальної коректності для всіх аргументів.

## Співвідношення з постійними прикладами

- `examples/fp_euler_reconstructed/` — Ейлер, 4 кроки, прийнятий B15, побітові результати.
- `examples/fp_rk4_reconstructed/` — RK4, 2 кроки, компенсаційне накопичення, прийнятий B16 R1; такий порядок підсумовування **більше не потрібен для перевіреного сценарію** з функціональним ROM B20, але чинний закомічений приклад не змінюємо.
- `reference/RK4_ORIGINAL_B16.k41` — демонструє, що саме зміна ROM вирішила попередній `HOLD` додавання двох від'ємних чисел.

**Межі доведеного:** 51 регресійний сценарій і дві конкретні RK4-ітерації, плюс раніше окремо доведені Ейлер і цикли. Немає перевірки фізичного «Києва», немає доказу достовірності всіх слів історичного лістингу, усіх умов переповнення, повного набору FP-функцій чи невідомої адреси `3574`.

## Розробницька дисципліна

Зміни мають залишатися ізольованими: вихідний 251-слівний файл, `mem/ROM.txt`, код CPU, `docs/historical/ROADMAP.md` і вже закомічені приклади не модифікувати. При оновленні CPU або оракула запускати повний gate і документувати новий evidence; поточний pinned B20 допускає лише перевірені SHA/Blob. Не видавати синтетичні слова `3706–3713` за архівно підтверджені історичні дані.
