# Метод Ейлера з рухомою комою на ЕОМ «Київ» (функціональна реконструкція)

**Статус:** `PASS_H115_B15_EULER_MACHINE_ODE_NOT_HISTORICAL` — один нативний запуск на незміненому продукційному CPU, підтверджений 619-командною трасою й 24/24 контрольними точками. **Не історична програма**: це сучасний приклад для реконструйованої програмної МП («машини з плаваючою комою») за Глушковим і Ющенко (1962). Збережений B15 native evidence перевіряється без доступу до зовнішніх ресурсів.

## Навіщо цей приклад

Продемонструвати роботу МП на **цілісній прикладній програмі**: виконання реального чисельного методу для ОДР, повторне використання проміжних значень, апаратне виконання інтерпретатора МП, машинний цикл і вихід за умовою. На відміну від історичної fixed-point програми Рунге—Кутти `libs/runge_kutta.txt`, цей приклад використовує саме програмну арифметику МП.

Розв'язуємо початкову задачу

    y'(t) = -y(t),  y(0) = 1,  h = 1/4.

Явний метод Ейлера обчислює `delta=h*y`, `y=y-delta`, `t=t+h`. Поріг `d=7/8-t` призначений **тільки для перевірки виходу із циклу**: після четвертої ітерації `d=-1/8`, тому не треба припускати неперевірену поведінку ±0. Це **демонстраційно фіксована** чотирикрокова задача, а не параметризований розв'язувач довільних ОДР.

| Ітерація | t | y (Euler) | delta=h*y |
|---:|---:|---:|---:|
| 0 | 0 | 1 | — |
| 1 | 1/4 | 3/4 | 1/4 |
| 2 | 1/2 | 9/16 | 3/16 |
| 3 | 3/4 | 27/64 | 9/64 |
| 4 | 1 | **81/256** | 27/256 |

Усі наведені числа точно представляються в реконструйованому 41-бітному форматі. Для порівняння, точний розв'язок ОДР у момент `t=1` дорівнює `exp(-1) ≈ 0.367879`, а наближення Ейлера — `81/256 = 0.31640625`. **Еталон машинного тесту — саме метод Ейлера, не exp(-t).**

## Збережена машинна програма

Файл [`inputs/EULER_IMAGE.k41`](inputs/EULER_IMAGE.k41) — оригінальний B15 13-слівний образ `KYIV41-OCT1` (сучасний HOST-контейнер, а не історичний формат перфокарт). Відповідний незалежний раціональний оракул — [`inputs/INDEPENDENT_ORACLE.json`](inputs/INDEPENDENT_ORACLE.json).

Усі адреси та слова — **вісімкові**. Програма не модифікує адреси команд і не використовує службову ОЗП МП `0001–0032`.

| Адреса | Команда | Семантика моделювання |
|---|---|---|
| `0230` | `11 0100 0101 0104` | `delta ← y * h` (множення з округленням) |
| `0231` | `02 0100 0104 0100` | `y ← y − delta` |
| `0232` | `01 0102 0101 0102` | `t ← t + h` |
| `0233` | `02 0103 0102 0105` | `d ← 7/8 − t` |
| `0234` | `31 0105 0235 0236` | Якщо `d` невід'ємне — `0235`; інакше — `0236` |
| `0235` | `31 0000 0230 0230` | Безумовний машинний перехід до початку циклу |
| `0236` | `33 0000 0000 0000` | Маркер завершення; на прийнятому маршруті **не виконується** CPU |

Дані: `0100=y` (початково 1), `0101=h` (1/4), `0102=t` (0), `0103=7/8`, `0104=delta`, `0105=d`. `0100`, `0102`, `0104`, `0105` змінюються **тільки машинними командами**, а не HOST між ітераціями.

## Швидкий запуск: уже підтверджений результат (Python 3.10+)

Із кореня checkout:

```bash
python -B examples/fp_euler_reconstructed/run.py --selftest && \
python -B examples/fp_euler_reconstructed/run.py --offline && \
python -B -m unittest discover -s examples/fp_euler_reconstructed/tests -p 'test_*.py' -v
```

`--offline` перевіряє вбудований `evidence/H115_B15_FP_EULER_ODE_EVIDENCE_V1.zip`: CRC, усі внутрішні SHA-256, контрольні точки, результати арифметики, 619 команд у трасі, відсутність CPU-виконання користувацьких FP-команд та звернень до невідомої `3574`. Потім друкує компактну таблицю `t,y`. **Це повторний аудит збереженого нативного запуску, а не нове виконання CPU.** Немає мережі, додаткових бібліотек чи залежності від `tempkyiv/h115_b15_v1`.

## Нове нативне виконання (MSYS2 MINGW64)

Потрібні GCC/G++ з C++17, Python 3.10+ та незмінні кваліфіковані джерела CPU і ROM. Скрипт звіряє Git-blob критичних C++ файлів з pinned baseline, а також байти `mem/ROM.txt` і 251-слівного друкованого FP-ROM. Якщо джерела змінено, native запуск **HOLD** до повторної кваліфікації.

```bash
python -B examples/fp_euler_reconstructed/run.py --native --repo . \
  --out tempkyiv/FP_EULER_NATIVE_REPLAY_01
```

Нові результати збережуться в `tempkyiv/FP_EULER_NATIVE_REPLAY_01/` та однойменному ZIP. Існуючі результати не перезаписуються. При помилці або розходженні скрипт зберігає доступні траси та `HOLD` у ZIP. Цей запуск **не змінює** `src/main.cpp`, історичний ROM, Git чи `ROADMAP.md`.

Нативний harness [`native.cpp`](native.cpp) **побайтово збережений із H115-B15**; він збирається разом із `src/main.cpp` і завантажує історичні 251 слово FP-ROM як основу. 7 приватних змін/доповнень машинних слів (`3455`, `3467`, `3470`, `3474`, `3476`, `3706`, `3707`) встановлюються лише в приватний ROM *конкретної сесії*. Дві адреси `3706` і `3707` не надруковані в книзі, тому їм **не надається історична автентичність**. Відсутню `3574` не доповнюємо.

Невірно запускати `image ... 0230` без МП: користувацькі FP-команди інтерпретуються через ROM-диспетчер, а не виконуються безпосередньо як апаратні fixed-point команди. Вхід у МП — NK `3000`, запуск CPU з `3300`; для програми користувача встановлюється адреса `0230`.

## Походження та межі перевірки

- Джерело реконструкції МП: Глушков, Ющенко, *Вычислительная машина «Киев»* (1962), друк. с. 111–118; точні слова історичної транскрипції — `examples/historical/gy1962/rom_modules/fp_simulation_251_printed.k41`.
- Оригінальний accepted H115-B15 evidence **збережено без змін**, SHA-256 та припущення наведено в [`PROVENANCE.json`](PROVENANCE.json).
- Звіт H115-B16 щодо *окремої* програми RK4 на момент додавання цього прикладу має `HOLD_CHECKPOINT_DRIFT`; він **не є** доказом працездатності RK4.
- Цей приклад підтверджує **скалярний Ейлер для фіксованих даних і приватного FP-ROM**, але не доводить правильність усіх FP-операцій, довільних ОДР, апаратної схеми чи автентичності історичної МП.

Це **постійний виконуваний приклад**, а не службова програма запуску H115-B15. Для бібліотечного/публічного інтерфейсу FP потрібна окрема задача; не слід перетворювати приватну реконструкцію на canonical ROM без додаткових джерел.
