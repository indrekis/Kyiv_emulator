# Ітераційна FP-програма для ЕОМ «Київ» — H115-B23

Це **нова навчальна машинна програма**, а не історично надрукований приклад. Вона виконується програмною МП із реконструйованого функціонального ROM. CPU лишається штатним `Kyiv_t`; HOST не обчислює рекурентну формулу.

## Задача

\[
x_0=1/4,\qquad x_{n+1}=\frac{x_n+1/2}{2},\qquad n=0,1,2,3.
\]

Обчислення чотирьох кроків дає послідовно `3/8`, `7/16`, `15/32`, **`31/64`**. Це не метод Ейлера й не RK4: окрема задача з новою RAM-програмою. Всі дроби точно представляються двійково.

## Адреси даних (вісімкові)

| Адреса | Значення |
|---|---|
| `0100` | Поточне `x`; спочатку `1/4`, після 4 кроків `31/64` |
| `0101` | Константа `1/2` |
| `0102` | Тимчасове `u = x+1/2` |
| `0103` | Лічильник часу `t`; спочатку `0` |
| `0104` | Крок `1/4` для `t` |
| `0105` | Поріг виходу `7/8` |
| `0106` | Ознака виходу `d=threshold−t` |

## Машинні команди

| Адреса | Opcode | Значення |
|---|---|---|
| `0300` | `01` | `u ← x + 1/2` |
| `0301` | `11` | `x ← u × 1/2` |
| `0302` | `01` | `t ← t + 1/4` |
| `0303` | `02` | `d ← threshold − t` |
| `0304` | `31` | Розгалуження за знаком `d`: вихід `0306` або продовження `0305` |
| `0305` | `31` | Безумовний перехід назад до `0300` |
| `0306` | `33` | Кінцевий маркер, **не виконується** з `--end-pointer 0306` |

Це FP-команди **користувацької програми у RAM**, які програмно інтерпретує МП у ROM. Звичайний CPU безпосередньо виконує лише машинні слова МП.

## Запуск штатним CLI

Потрібна зафіксована гілка з універсальним режимом `fp-image` (H115-B22 R2). Із кореня репозиторію, в MSYS2 MINGW64:

```sh
mkdir -p tempkyiv && \
g++ -std=c++17 -O0 -Iinc src/main.cpp src/asm_disasm.cpp -o tempkyiv/kyivemu_fp.exe && \
ROM=examples/fp_rom_reconstructed/inputs/FP_FUNCTIONAL_1962_RECONSTRUCTED.k41 && \
ROM_SHA=$(sha256sum "$ROM" | cut -d' ' -f1) && \
./tempkyiv/kyivemu_fp.exe fp-image \
  examples/fp_affine_recurrence/inputs/AFFINE_RECURRENCE.k41 \
  0300 2500 --fp-rom "$ROM" --fp-sha256 "$ROM_SHA" \
  --end-pointer 0306 --watch 0100 --watch 0102 \
  --watch 0103 --watch 0106
```

Очікуємо `H115-FP-RUN STATUS=END_POINTER`, `DISPATCHES=24`, `POINTER=0306`, `C=3305`. Кінцеві машинні слова:

```text
0100 (x) = 17400000000077   # 31/64
0102 (u) = 17400000000100   # 31/32
0103 (t) = 10000000000101   # 1
0106 (d) = 30000000000076   # -1/8
```

Точну кількість *внутрішніх* команд МП визначає нативний запуск: вона залежить від шляхів нормалізації, а не тільки від кількості FP-команд. Зафіксований H115-B23 evidence після приймання міститиме цю кількість.

`--end-pointer` — умова завершення HOST на межі диспетчера `3305`, **не** історична команда STOP. Історична транскрипція 251 слова залишається незмінною. Новий приклад не доводить достовірність реконструйованого ROM для фізичної ЕОМ.

## Відтворюваність

```sh
python -B examples/fp_affine_recurrence/oracle.py --verify && \
python -B -m unittest discover -s examples/fp_affine_recurrence/tests -p 'test_*.py' -v
```

Оракул побудований тільки на `fractions.Fraction` (без викликів CPU або C++ арифметики). Native gate H115-B23 додатково перевіряє 1, 2, 3 і 4 ітерації: для цього на *тимчасових копіях* програми змінюється виключно комірка порогу `0105`; постійний файл залишається незмінним.

Історичне джерело МП: Глушков, Ющенко (1962), друк. с. 111–118. Розмежування історичного та функціонального ROM: `docs/historical/H115_FP_ROM_PRINTED_VS_FUNCTIONAL.md`.
