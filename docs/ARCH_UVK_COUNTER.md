# УВК (`C`) — 11-бітна адреса, 10-бітний послідовний лічильник

**Статус джерела:** `SOURCE-CONFIRMED` для розділення молодших 10 лічильних розрядів і 11-го розряду виду пам'яті. **Статус H25/H17:** `PRIVATE_NATIVE_PASS` за журналом користувача (4/4), без змін production. **H25/H18R2:** `NATIVE_REGRESSION_PASS` (ISA 23/23 та H24 282/282, HOST-only де зазначено). **H25/H19R2:** `STAGED_INTEGRATION_VERIFIED` (індекс 7/7; нативні перевірки на фактичному CPU). Це не апаратний еталон.

## Першоджерела й границі тверджень

- В. М. Глушков, Е. Л. Ющенко, *«Вычислительная машина Киев»* (1962), друк. с. 9–10, 55, 165, 167: 11-розрядний лічильник, окремий тест розрядів 1–10 і тест 11-го; оригінальний маршрут `1777 → 0000 → 0001 → 0251` реконструйований зі слів історичної програми.
- Л. Н. Дашевський, С. Б. Погребинський, Є. А. Шкабара, *«Вычислительная машина „Киев“ (Проектирование и эксплуатация)»* (1964), **друк. с. 158**: УВК має 11 розрядів; **перші 10 працюють як лічильник**, 11-й означає *вид пам'яті*; він приймає код з 11-ї адресної шини третього поля РК або регістра повернення РВ.
- Там само, с. 156–157, **рис. 74**, с. 168–169, **рис. 78**: джерела адрес для УВК, розділення сигналів приймання нового коду й керування.
- Там само, с. 176, **рис. 84**, с. 177, **рис. 85**: окремий керувальний імпульс `«+1» УВК` для послідовної вибірки. **Схеми не містять повної топології перенесень** між усіма тригерами. Відсутність перенесення в 11-й біт підтверджується насамперед прямим текстом с. 158, не домальованими вентилями.
- Увага: **11-й тригер суматора адрес СмА** сигналізує переповнення й **не є** 11-м розрядом УВК.

## Два несумісні за семантикою механізми зміни `C`

Усі адреси та константи нижче — **вісімкові**. Для одинадцятибітних `C`:

```cpp
// Sequential step, and each sequential step in a command skip:
next_sequential_C(C) = (C & 02000) | ((C + 1) & 01777);
```

| `C` до | Після послідовного кроку | Що перевіряється |
|---|---|---|
| `0000` | `0001` | Звичайний приріст |
| `1776` | `1777` | Останній крок перед межею |
| **`1777`** | **`0000`** | Переповнення молодших десяти розрядів, 11-й = 0 |
| `2000` | `2001` | Послідовний приріст зі встановленим 11-м бітом |
| `3776` | `3777` | Перед межею з 11-м бітом = 1 |
| **`3777`** | **`2000`** | Переповнення молодших десяти розрядів **зі збереженням** 11-го |

Ця таблиця задає **вміст регістра**, не гарантує фізичної доступності наступної комірки. Зокрема, тест `3777→2000` не дозволяє робити висновок про виконуваність команд із ділянки `2000..2777` реальної машини.

**Пряме завантаження** (`C ← a2/a3`, `C ← P`) принципово відмінне: приймається **повна 11-бітна адреса**, у тому числі біт `02000`. Ніякого виклику `next_sequential_C` у гілці взятого переходу, повернення чи вибору адреси на завершенні групової операції бути не повинно. У `32`/ПРВ регістр `P` копіюється до `C`, потім `P` обнуляється; у `30`/УПП при взятому переході завантажуються адреси `C` і `P`. Старі невирішені суперечності щодо модифікації полів `30` залишаються відкритими й цим патчем не вирішуються.

## Вплив на сімейства інструкцій

| Механізм | Команди / гілки | Політика C |
|---|---|---|
| Звичайне продовження | `00`, арифметика, логічні, Ф (`34`), читання `20/21`, підготовка `25` | Один `next_sequential_C` |
| Умова не виконана | `04`, `05`, `16`, `30`; `26`, якщо `A≠Ц` | Один `next_sequential_C` |
| Пропуск після блокованого переповнення | Арифметичні гілки з двома послідовними кроками | **Два** незалежні кроки `next_sequential_C`; це не 11-бітне `C+2` |
| Явне керування | Взяті `04/05/16/30`, обидві гілки `31`, переходи `26/27`, `32`, барабанні `23/24` | Присвоєння повної адреси; не застосовувати low10-маску до адреси переходу |
| STOP та арифметичне аварійне завершення | `33`, `12` (ділення на нуль), переповнення | Наявне просування `C` — **HOST спостереження / політика**, а не засвідчений апаратний стан після останову |
| Спеціальний передвибір | `25`, гілка з `experimental_drum` | Адреса `next` до перевірки пам'яті має бути обчислена через `next_sequential_C`; лише після успішної перевірки змінюється стан барабана |

**Важливе місце H18:** до приватної трансформації H17 входили тільки **23** інструкції `++C_reg`, але в тілі opcode `25` є **24-й шлях** — `const addr_t next = C_reg + 1`. Не виправляти лише 23 входження. Виправлення `25` зберігає вже реалізовані перевірку наступної команди до коміту стану, передвибір `K`, fail-closed і транзакційність; не змінює розшифрування команди магнітного барабана.

## Історична верифікація та межі регресій

- H25/H16: незмінений CPU дав `C=2000` після виконання оригінальної команди за `1777`, 4/4 нативних сценаріїв (розбіжність із маршрутом тесту).
- H25/H17: приватна кандидатна збірка пройшла `1777→0000→0001→0251` без редагування історичних слів; 4/4, існуюча `ISA-05 D4` PASS. Це **не** підтверджує весь тест УУ або всю архітектуру машини.
- H25/H18: окремі граничні проби на `1777` і `3777`, прямі завантаження повного `C`, регресія 25, широкі ISA-05/ISA-06 і H24 з реальною збіркою CPU. Нативний журнал MSYS2 H18R2 підтвердив ISA 23/23 і H24 282/282; H19R2 підтвердив незмінність усіх семи staged-файлів та нативні перевірки вже робочого CPU. HOST-еталони не є апаратним оракулом.
- Залишаються відкритими попередні суперечності джерел, деякі крайові значення А/Ц, рівність opcode `04/05`, стан `C` після STOP, апаратні затримки й 11-й розряд у недоступних гілках реального ЗП. Жодного нового апаратного оракула немає.

Це уточнення не змінює машинні слова історичних тестів, RAM- або ROM-образи, значення мнемонік чи результати старих перевірок, не пов'язані з межею лічильника.
