# ISA-07 D14-B1 — автономна модель логічного барабана

**База:** `9d45a0262e7bce6268cbf50282443ad2b863ac06` (D14-A).  **Статус:** незалежне сховище; жодної інтеграції з `Kyiv_t`. **HARDWARE_ORACLE=0**.

## Межі цього етапу

Додано лише `inc/kyiv_drum_logical_media.h`, standalone C++-probe, незалежний Python-sandbox та read-only аудитор. Підтримано зберігання *точного* 41-бітного машинного коду, окремий стан `UNWRITTEN`, відокремлення комірок за координатами та копіювання образу. Немає `25`-декодера, автоматичного перемикання тракту, групових передавань, дискового образу, фізичного кодування або змін CPU. Тексти старих тимчасових адаптерів `23/24` не визначають цей API.

## Контракт C++17

```cpp
#include "kyiv_drum_logical_media.h"
using namespace kyiv_drum_media;
logical_media m(geometry{"test-mini-2x3x4", 2, 3, 4});
m.store({0, 0, 0}, 0);           // WRITTEN +0
m.store({0, 0, 1}, sign_bit);    // WRITTEN -0 (sign and zero magnitude)
cell first = m.inspect({0, 0, 0});
cell second = m.inspect({0, 0, 1});
```

- `geometry` обов'язкова та явна; профілю за замовчуванням немає. `profile_id` — непорожній ASCII-токен `A-Z a-z 0-9 . _ -`, не більш ніж 64 символи. Він є позначкою *експерименту*, не підтвердженням історичної геометрії.
- Координати `{drum,track,slot}` — **нуль-базовані індекси HOST_API**. Не плутати з історичним номером тракту (до 24), полем II команди `25` або внутрішніми регістрами МЗУ. Відповідне декодування залишається `OPEN`.
- Дані `uint64_t`: дозволені рівно біти 0..40; старші біти відхиляються як `INVALID_WORD`, а не обрізаються. `+0=0`, `−0=1ULL<<40` зберігаються побітно; `WRITTEN +0` відрізняється від `UNWRITTEN`.
- `inspect` повертає `cell{written,word}`. Для `UNWRITTEN` значення `word` не має семантики. Цей API **не обирає** історичної реакції на читання незаписаного барабана.
- `store`/`erase` — лише одиничні операції. Некоректна координата або слово відхиляються **до** зміни будь-якої комірки чи `written_count`. Перезапис не збільшує лічильник. Семантику групової атомарності реалізує D14-B2.
- Копіювання `logical_media` зберігає повну геометрію, стан `written` та сирі біти; подальші зміни копії ізольовані від оригіналу. Це підґрунтя для staging у D14-B2.
- Розмір масиву (`drums × tracks_per_drum × slots_per_track`) перевіряється перед виділенням пам'яті; переповнення `size_t` відхиляється як `GEOMETRY_OVERFLOW`. Обмеження `1,000,000` слотів — **HOST_POLICY** захист від необмеженого виділення, не фізична характеристика.

## Геометрія і джерела

D14-A встановлює суперечність: GY62 — максимум `9864` кодів для трьох барабанів; DPS64 — `511` кодів на тракт. Число `137 = 9864/(3×24)` лише арифметичне. Тому `experiment-137` (`3×24×137`) і `experiment-511` (`3×24×511`) — **тільки явно задані тестові профілі**. `2×3×4` служить малим незалежним тестом індексації. Жодна з конфігурацій не є мовчазним типовим значенням.

## Тестування

```sh
g++ -std=c++17 -O0 -Wall -Wextra -pedantic -Werror -Iinc \
  tests/isa/isa07_d14b1_logical_media_probe.cpp -o tempkyiv/d14b1_media.exe
python tools/isa07_d14b1_logical_media_sandbox.py \
  --exe tempkyiv/d14b1_media.exe --random-steps 200 --timeout 5
```

Python задає серії операцій і **незалежно** моделює очікуваний стан словником координат. Кожна відповідь C++ звіряється з очікуваною; ініціалізаційні помилки перевіряються окремо. Жодних залежностей від `src/main.cpp`, фізичного `Kyiv_t`, старих файлів барабана або мережі.

## Відкладене та невідоме

**D14-B2:** групові атомарні передавання та переключення тракту лише за явним provisional-профілем. **D14-B3:** власний бінарний формат зі схемою, хешем і commit. **D14-C:** інтеграція `25→23→25→24`, реальні CPU-кроки й регресії. Невстановлені геометрія, кодування полів команди `25`, поведінка після 24-го тракту, ROM-джерело `23`, ефект на регістр `A`, фізична реакція на непідготовлений осередок і crash-durability залишаються `OPEN`. Застосування цього HOST_API не закриває жодного з них.
