# ISA-07 D14-C1f — кінцева адреса підготовки МБП: джерела та неоднозначність

**Baseline:** `297c4a113a5eee0b469625d7646e9c5eeac1b2e8` (D14-C1e).

**Scope:** SOURCE REVIEW + independent bit-arithmetic witness. No CPU, controller, B1/B2/B3 or `.kdr` changes. `HARDWARE_ORACLE=0`.

## Кваліфіковані твердження першоджерел

- **GY62, друкована с. 15:** команда `25` використовує **немодифіковану** II адресу для барабана і тракту, III адресу — для номера початкового коду *в обраному тракті*; I адреса задає напрям. Для номера барабана відведено третій вісімковий розряд II адреси. Це **SOURCE_STRICT** для слів автора, **не** доказ маски тракту.
- **GY62, друкована с. 59:** формальна адресна модель `a₂ = k·2⁻²²`, `k∈{1,2,3}` (номер МБ); `a₃` — початковий номер коду. Для 40-бітного дробового модуля це дає `raw40=k<<18`; у 41-бітному машинному слові II поле стоїть у бітах 12–22, отже `raw_a2=k<<6` (`0100/0200/0300` octal). **SOURCE_DERIVED** точне позиціювання drum digit для цього представлення. Сторінка 59 **не містить повної формули тракту**.
- **GY62, с. 83:** вміст ПЗУ `3040` дорівнює `2⁻¹²`; множення `0011: 10 3000 3040 0060` переводить позитивний параметр `n` з I адресного поля НК `3000` у поправку `n<<12` до машинного слова. Формула **умовна**: інші розряди НК та округлення можуть змінювати результат.
- **GY62, с. 124 і 177–179:** НК `3002` має позначення `0k00 | b`, де `k=1,2` для двох барабанів, `b` — початкове місце; `0016/0017` додають це до підготовки запису/читання, `0035/0036` додають вміст `0060` до тих самих підготовчих команд. Це **SOURCE_DERIVED** для структури тесту; не самодостатня апаратна адресація.
- **DPS64, друкована с. 231–233:** у вузлі керування МЗУ код початкового номера місця подано як один **13-розрядний** код: біти `КШП1–8` надходять у лічильник місця, `КШП9–13` — у лічильник тракту. Авторський приклад: десяткове `612 → тракт 2, місце 100` (`612=2·256+100`). Це **SOURCE_STRICT щодо внутрішніх лічильників**, але джерело не дає достатнього перетворення програмних полів `25` на всі `КШП1–13`.
- **DPS64, с. 231:** одночасно сказано про `511` чисел на тракт. Це **OPEN_CONFLICT** із простим 8-бітним лічильником місця; не виправляємо текст автора заднім числом і не прирівнюємо автоматично до геометрії GY62 (`9864` кодів для 3 барабанів на с. 5–6).

## Числова неоднозначність, яку виявляє C1d/C1e

Якщо початкова II адреса `0100` отримує додатну поправку `n=64` (додавання `0060=n<<12` до слова), виникає `0200`. Точне таке саме кінцеве II поле дає вихідна адреса `0200` з нульовою поправкою. Для однакових `a₁/a₃` **цілі машинні команди однакові**. Аналогічно `0100+0200=0300` та `0200+0100=0300` (усе octal). Це `MATH_PROVEN`: **саме кінцеве слово не відновлює історії його створення**. Це **не** доказ того, що реальний пристрій має запам'ятовувати первинний барабан: апаратна семантика двох ідентичних кодів може бути однаковою.

Тест C1e вже показав `76/76`, `532` реальних CPU-кроки, збіг обчислення команд з еталоном. Він **не** перевіряв фізичне трактування отриманих адрес пристроєм.

## Рішення для інтеграції

- `SOURCE_STRICT`: напрям 0/1 та використання сирих II/III полів для `25`; не змінювати цю поведінку у зв'язку з невизначеністю лічильників.
- `SOURCE_DERIVED`: виділення барабана `(raw_a2>>6)&7` для кваліфікованих початкових векторів `0100/0200/0300`, *без ствердження повного статичного поділу II поля*.
- `OPEN`: повне декодування тракту, початкового місця/нумерації, переповнення, `511` vs внутрішні 8 біт vs `9864` загалом, взаємодія реального 13-бітного КШП з II/III полями.
- `HOST_POLICY` для майбутнього обмеженого proof-of-integration: геометрія задається явно; приймаємо тільки `raw_a2 ∈ {0100,0200,0300}` (без зміщення у II та без інших бітів); `raw_a3` інтерпретується тільки згідно з **іменованою експериментальною** політикою позиції (0-based), без претензій на історичну нумерацію. Усі інші II адреси — `UNQUALIFIED_TRACK_MAPPING`, жодного мовчазного переходу на інший барабан. Ця пропозиція не реалізована і не доведена джерелом; для CPU-інтеграції потрібен окремий explicit-mode gate.

**Release gate:** не вводити історичної геометрії або decoder track mask за замовчуванням; повний апаратно-достовірний обмін не заявляти до додаткових джерел і верифікації. Рекомендований наступний крок — документований HOST_POLICY контракт мінімальної інтеграції і справжні CPU-тести `25→23→25→24` у вибраному експериментальному режимі. Не ототожнювати це з реконструкцією апаратних лічильників.
