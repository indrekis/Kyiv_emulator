# ISA-06 D5 — bounded write/read iterations of the fourth historical RAM test

**Base:** `7e98949` (ISA-06 D4). Two new files only; **no edits** to CPU, ROM, existing tests, the root README, or the historical-program corpus. This is an ISA/integration *characterization* with explicitly controlled memory.

## Evidence and provenance

- Glushkov–Yushchenko (1962), Appendix 2, **printed p. 170**: the fourth RAM diagnostic uses a traveling one/zero, writing during **0122–0136** and reading/checking during **0140–0155**.
- GY62, **printed p. 171**: 27 complete original instruction words used by this probe (octal 0122–0136 and 0140–0155). They are transcribed in `HIST`, not regenerated by the emulator's assembler; the words and addresses are historical, but this does **not** authenticate initial RAM/ROM.
- GY62, **printed pp. 9, 12–14**: indexed address modification, `13` 41-bit shift, `16` exact code comparison, `26` raw field initialization, `27` loop step/wrap, `31` sign branch, `33` stop.
- Dashevsky–Pogrebinsky–Shkabara (1964), **printed pp. 18–22, 160–163**: instruction semantics and control organization, corroborative context, not independent proof of ROM values.

## Controlled initial environment

All tests construct `Kyiv_t` and inject **ROM 3012=000...001, 3026=200...000 (-0), 3042=100...000 (top magnitude bit)** with `write_rom` to bypass the known CWD-dependent constructor path. They reflect the current *human-transcribed* `mem/ROM.txt`, **not independently certified historical ROM**. The machine words are authentic but initial memory values are a fixture. Other preconditions: RAM `0014=+0` chooses the positive sign branch of `31`; RAM `0021` starts with `-0` for STRICT control-flow-only scenarios or positive **1** for the POLICY full-loop cases. Checks include fetched `K`, every PC transition, bounded step count, execution status, preserved P, selected A/Cy and memory outputs. No full historical RAM-test PASS is claimed.

## Classification: STRICT, POLICY, OBS

| Scenario | Original addresses executed | Class | What is actually asserted |
|---|---|---|---|
| Write -0 control iteration | 0122,0123,0124,0126,0127,0130,0135,0136 | **STRICT** | Branch topology, +1 reset at 0021, A=0201, C=0123; **not** zero sign after arithmetic copies |
| Write 1777 wrap/exit | 0123,0124,0126,0127,0130,0135,0136 | **STRICT** | A wraps to 0000, C exits to 0137; **not** sign of memory at 1777 |
| Read prepared comparison tail | 0144,0146,0147,0154,0155 | **STRICT** | Preloaded 0020 and 0200 are equal -0; exact compare, reset, A=0201, C=0141 |
| Read prepared mismatch | 0144,0145 | **STRICT** | Distinct preloaded 0020/0200 cause original 33 stop instruction to run; PC **after** stop is recorded, not asserted |
| Two uninterrupted positive write iterations | 0122–0136 (selected PCs), two loops | **POLICY** | 0200=1, 0201=2, 0021=4, A=0202, C=0123 |
| Two uninterrupted positive read/check iterations | 0140–0155 (selected PCs), two loops | **POLICY** | 0200=1/0201=2 verified, 0021=4, A=0202, C=0141 |
| Read prefix with -0 | 0140 onward, bounded to five steps | **OBS** | Actual branch after arithmetic copying `(-0)+(+0)`; no normative result |

**Critical limitation:** D4 OBS identified an unresolved historical sign for `01` applied to `(-0)+(+0)`. This occurs **already at 0123** when a negative zero is propagated to RAM and **at 0141** on read-back; therefore the D5 `STRICT` write control cases deliberately do not assert the sign/value of RAM 0020 or its indexed copy. The `STRICT` read tail begins **after** that ambiguous arithmetic copy with independently preinitialized equal operands. The uninterrupted positive write/read sequences avoid this ambiguity using nonzero inputs, but each depends on the preserved emulator equality branch for `05` (0==0), which remains **POLICY** from ISA-05; tests do not promote it to historical fact. `POLICY-FAIL` is distinct from `DOC-MISMATCH`.

The STOP case checks actual stop and original fetched `K` but deliberately does not assert the post-stop `C`, since the historical state of the instruction counter after STOP is not independently established.

The final `OBS` runs a short true program prefix with a `-0` source and original RAM comparator: it is *informative*, not a failure oracle. None of these tests validates the historical correctness of ROM transcriptions, RAM fault behavior, exact error-stop panel behavior, the branch rules for `04/05` equality, or the entire storage diagnostic.
