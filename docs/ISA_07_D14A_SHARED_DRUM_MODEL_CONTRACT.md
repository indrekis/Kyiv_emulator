# ISA-07 D14-A — контракт майбутньої спільної моделі МБ

**Статус:** ARCHITECTURE PROPOSAL, **NOT IMPLEMENTED**, parent `9e9ff811f6199991f782fb2fd69549135a78a1d9`.

## 1. Розділити пристрій, контролер і збереження

1. **LogicalMedia**: масив/мапа 41-бітних *сирих* кодів, ключ **(номер барабана, тракт, місце)**. Жодних десяткових конверсій. Зберігати знак `−0` та командні слова. Невідомий/незаписаний осередок позначати окремо (`UNWRITTEN`) — політика читання ще `OPEN`.
2. **DrumController**: `prepare(direction, raw_a2, raw_a3)` і `transfer(raw_a1, raw_a2, branch_a3, RAM/ROM)` з розрізненням *нештрихованих* полів підготовки від ефективних адрес передачі. Розбирати `25` та дозволені напрями тільки після окремого аудиту точного bitfield-кодування (GY62 с. 15, 59; DPS64 с. 231). Стан підготовки має містити `valid`, `direction`, `drum`, `track`, `position`, а не старі рядки/байтові зміщення.
3. **MediaPersistence**: новий власний `HOST_POLICY` формат з магічним заголовком, версією, явною геометрією/профілем, канонічним порядком байтів, маскою записаних слів та контрольними сумами. Не називати його образом *оригінального* барабана. Заміна файла через тимчасовий sibling та перевірений commit; crash durability й concurrency залишаються `OPEN`.
4. **EmulatorAdapter**: тільки CPU-рівень і стан регістрів. Перший D14-C тест має зробити реальні `25(write) → 23 → 25(read) → 24`, перевірити покрокові `C/K`, бітову тотожність, відсутність збоїв та збереження знакового нуля.

## 2. Геометрія і неоднозначності

**Зафіксовані джерелом:** 3 барабани, останній 24-й тракт, 41-бітний код, автоперехід на наступний тракт. **Не фіксувати поки:** ємність одного тракту, відповідність 9864↔511, відображення 11-бітного поля II у `(drum, track)`, діапазон позиції, необроблене заповнення, реакцію на переповнення 24-го тракту.

Для тестів D14-B дозволено **тільки явний PROVISIONAL profile**, наприклад `profile_id=experiment-137`, з параметрами `drums=3, tracks_per_drum=24, slots_per_track=137`. Число 137 — *лише арифметика* `9864/(3*24)`, не історична істина. Окремий `experiment-511` — також тестова конфігурація, не рішення щодо фізичної геометрії. **Не вибирати жоден з них silently як default.** Краще тестувати `2×3×4` міні-геометрію, щоб відділити правильність адресації від питань історії.

Додатково на DPS64 с. 231 згадано поділ початкового номера: `КШП1–8` — лічильник місця, `КШП9–13` — лічильник тракту. Це джерельна зачіпка для майбутнього декодера, але **не доказ**, що програмне 11-бітне поле `a₂` кодується так само, як внутрішній регістр адреси МЗУ.

## 3. Операційні гарантії

- Усі входи перевірити до зміни RAM/образу/`C/K`: 41-бітність коду, стан підготовки, напрям, межі доступу, кількість слів, перетин 24-го тракту.
- На записі сформувати **всю** операцію змін на копії журналу/сектора образу, перш ніж фіксувати; за помилки не залишати часткових змін. Повна crash consistency та мікросекундна синхронізація — не вимога цифрового ISA-емулятора наразі.
- На читанні не змінювати RAM до успішної перевірки всього діапазону. Для непідготовленої/неініціалізованої позиції — явна `HOST_POLICY` помилка до окремого рішення.
- Не зберігати поточне `D13-B` обмеження «тільки RAM» для `23` як автоматичну історичну вимогу: джерела 1962 р. щодо ПЗУ суперечливі.
- Апаратне знищення адресного модифікатора — кандидат на **окрему ISA зміну**, не домішувати в D14-B API тест.

## 4. Наступні acceptance gates

**D14-B (API, без CPU):** геометрія/межі; усі 41 біти, `−0`; інтервали; ізоляція 3 барабанів і 24 трактів; перехід між трактами й відмова на останньому; serialize/deserialize точний round trip, версія/хеш/пошкоджений образ, atomic failure. Для PROVISIONAL профілю — не робити `HARDWARE_ORACLE=1`.

**D14-C (CPU):** реальні 4+ кроки `25→23→25→24` (плюс фінальний XOR/STOP як негативний свідок), незалежний оракул 41-бітних даних, підтвердження вибору барабана/тракту/початкового місця, випадки перемикання тракту, завершення `C/K` та відмови без часткового запису; окремий режим без диска для API та persist для реального образу. Архівні старі host-path тести позначати `ARCHIVED`, не переписувати.

**Блокер перед SOURCE_STRICT geometry:** додаткова звірка 9864 проти 511, кодування II поля та поведінки крайових трактів. Поки не усунуто — не заявляти історичну повноту D14-C.
