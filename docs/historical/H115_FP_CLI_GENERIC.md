# H115-B22 R2 — загальний HOST-запуск програм МП «Києва»

**Область:** необов'язковий CLI-режим `fp-image`, а не новий емулятор CPU і не нове історичне ПЗП. МП залишається машинною програмою в змінно-спаяній пам'яті `3300–3777`. Універсальний інтерфейс лише задає початковий стан та зупиняє прогін у визначеній користувачем точці.

## Команда

Скомпілюйте звичайний `kyivemu` та запускайте з кореня репозиторію:

```sh
kyivemu fp-image PROGRAM.k41 ENTRY_OCTAL MAX_STEPS_DECIMAL \
  --fp-rom FP_ROM.k41 --fp-sha256 EXACT_SHA256 \
  [--end-pointer END_OCTAL] [--watch ADDRESS_OCTAL]... \
  [--trace-steps] [--verbose-cpu]
```

Обидва файли мають формат `KYIV41-OCT1`. `PROGRAM.k41` містить слова RAM `0001–1777`, FP-ROM — слова змінної пам'яті `3300–3777`. `--fp-sha256` є обов'язковим SHA-256 **байтів** обраного ROM; він не повинен збігатися з якимось жорстко зашитим хешем. **SHA-256 програми не обмежується**: можна подавати власний RAM-образ. Потрібно явно вказувати ROM; за замовчуванням він не підставляється.

Стандартне постійне ПЗП `3010–3277` завантажується з `mem/ROM.txt` через уже наявний SHA-pinned механізм; файл ПЗП не змінюється. Емулятор один раз задає пультове слово `НК 3000 = ENTRY << 12`, вибирає пультове джерело 3000, вмикає блокування **аварійного** останову та встановлює `C=3300`. Далі машинні команди виконує **той самий продукційний `Kyiv_t`**. Після старту HOST не змінює `C` і не коригує результати арифметики.

Параметр `--end-pointer` задає адресу, яку інтерпретатор прочитає як наступну команду користувацької програми. Під час повернення МП до диспетчера `C=3305` HOST зупинить прогін, якщо покажчик `RAM[0014]` збігається з цією адресою. Для програм із STOP-маркером це зупинка **перед** інтерпретацією маркера, як у перевірених прикладах. Без параметра нормальний вихід можливий лише через справжній останов CPU; інакше досягнення `MAX_STEPS` дає `FP_STEP_LIMIT` і ненульовий код повернення. Вказаний `--end-pointer` має бути присутнім у RAM-образі, але не потребує конкретного opcode чи сусідства з `ENTRY`.

`--watch` можна застосовувати до довільної доступної RAM/ROM-адреси, включно з `3000–3007`. Звичайний режим **не містить** `readable()`/opcode-allowlist, не забороняє штатні звернення до НК, постійного ПЗП, вводу/виводу або довільних адрес RAM. Їхню семантику забезпечує CPU. У загальному режимі читання не відтранскрибованого `3574` не оголошується історично достовірним: пам'ять емулює наявний образ, а невідомі значення можуть бути нульовими. Для історично контрольованого виконання використовуйте окремі *суворі регресійні runner*, які спеціально перевіряють доступи до невідомих адрес.

## Приклади, перевірювані окремим тестовим гейтом

```sh
ROM=examples/fp_rom_reconstructed/inputs/FP_FUNCTIONAL_1962_RECONSTRUCTED.k41
ROM_SHA=$(sha256sum "$ROM" | cut -d' ' -f1)

./tempkyiv/kyivemu.exe fp-image \
  examples/fp_euler_reconstructed/inputs/EULER_IMAGE.k41 \
  0230 2000 --fp-rom "$ROM" --fp-sha256 "$ROM_SHA" \
  --end-pointer 0236 --watch 0100 --watch 0102

./tempkyiv/kyivemu.exe fp-image \
  examples/fp_rom_reconstructed/reference/RK4_ORIGINAL_B16.k41 \
  0240 2000 --fp-rom "$ROM" --fp-sha256 "$ROM_SHA" \
  --end-pointer 0265 --watch 0100 --watch 0101
```

`kyivemu` і `tempkyiv/kyivemu.exe` тут назви/шляхи з прикладу, не гарантія збірки. Приклади виводять `H115-FP-RUN STATUS=END_POINTER`, точний сирий вміст `y` і `t`, кількість кроків і меж диспетчера. **Очікувані значення не закодовані в загальному CLI.** Їх перевіряє окремий тест `tests/historical/test_fp_cli_generic.py` і stage-native-gate.

Прийнята траєкторія Euler: 623 кроки, `0100=12100000000077`, `0102=10000000000101`. Початковий RK4: 1305 кроків, `0100=11550631000100`, `0101=10000000000100`. Це спостереження на функціональному реконструйованому ROM, а не доказ автентичності фізичної машини.

## Межі

- Валідація SHA-256 захищає від випадкової/неавторизованої підміни обраного ROM, але не підтверджує його історичну правильність.
- Параметр `--end-pointer` — HOST-умова припинення виконання на межі диспетчера; вона **не є** історичною машинною командою STOP. Справжній STOP CPU підтримується окремо.
- Інтерпретатор у ROM використовує робочі комірки RAM, тому довільний користувацький образ може конфліктувати з його службовою пам'яттю. Загальний CLI не приховує таких конфліктів і не обіцяє правильність будь-якої програми.
- Будь-який синтаксично коректний SHA-pinned ROM (змінна пам'ять `3300–3777`) допускається до запуску. Позитивні математичні результати кваліфіковані **лише** для збереженого функціонального образу. Оригінал `fp_simulation_251_printed.k41` залишається без змін та не вважається повністю працездатним.
- Це початковий інтеграційний CLI. Тут немає реалізації символьного асемблера FP-команд, роботи з реальним пультом або автентичної моделі периферії.
- Продукційний `src/main.cpp`, `inc/kyiv.h`, `mem/ROM.txt`, історична транскрипція і збережені приклади не змінюються.
