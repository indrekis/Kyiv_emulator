# H118-P2-B — двоепохна функціональна демонстрація тесту АУ в Qt

**Статус:** `ACCEPTED_NATIVE_AND_MANUAL_QT`; `FUNCTIONAL_RECONSTRUCTION`. Нативний gate і ручне приймання Qt пройдено.

## Джерела та склад образу

- 20 канонічних H37/H52 `.k41` із 220 унікальними RAM-адресами; їх не змінюємо.
- `0042: 01 3066 0000 0353` — окремо підтверджене друкованим джерелом слово.
- `0360: 05 0000 0000 0042` — **функціональна реконструкція** H117, не транскрипція.
- НК `3000 = 20000000000000` — H117 HOST-початковий стан.
- ПСП `mem/ROM.txt` і C++ `Kyiv_t` залишаються незмінними.

Новий образ `examples/operator_scenarios/inputs/au_h117_two_epochs.k41` **генерується** з H117 source set у приватному shadow і потім фіксується SHA-256 у C2b-маніфесті. Він містить 222 RAM-слова та не замінює канонічні зображення. ROM-set `math_module1` використовується лише як наявний інфраструктурний C1a комплект; gate відхиляє будь-яке виконання змінної ПЗП `3300..3777` у трасі АУ.

## Виконання й oracle

1. **Контрольний native-сеанс без слова `0360`**: перший прохід має завершитися на `C=0360` після 97 машинних команд.
2. **Окремий native-сеанс зі словом `0360`**: перший прохід і RAM `[0347,0353,0357]` збігаються з контролем; 98-ма команда виконує `0360 → 0042`; друга епоха досягає `C=0360` **без скидання CPU**.
3. На підставі пройденого H117 обмеженого oracle `tools/historical/au_h117_two_epoch_c2b_v1.py` створює точний план дій C2b: адресу кожної машинної команди, `A`, `P`, `T`, `STEPS`, контрольні слова першої межі. Кількість команд другої епохи береться із фактичного H117 native результату, а не встановлюється довільно.
4. **Незалежне повторне виконання C2b** запускає SHA-закріплений складений образ через той самий production Qt backend і порівнює кожну групу машинних команд зі збереженим планом. Так перевіряється інтеграційна відтворюваність між двома шляхами запуску одного CPU; сам по собі цей збіг не перетворює реконструйоване слово на джерельне.

Звичайні C2a/C2b регресії та Qt smoke виконуються у приватному shadow до зміни tracked-файлів.

## Як дивитися у Qt

1. `bash gui/qt6/run.sh`, поле **«Сценарій оператора»** → `au_h117_two_epochs`, натиснути **«Відтворити й перевірити»**.
2. У статусі вікна й трасуванні з'явиться **епоха 1, 97/97, `C=0360`**.
3. Окремим кроком відобразиться **функціональна реконструкція `0360 → 0042`**.
4. Друга епоха продовжить **той самий CPU**, без перезавантаження. У завершальному стані `C=0360`, а сума виконаних команд дорівнює `98 + кількість команд другої епохи` за прийнятим C2b планом.
5. Очікувано `C2b PASS`; усі фактичні адреси, `A/P/T/STEPS` та три слова пам'яті на першій межі мають збігтися з планом. За будь-якої невідповідності — `HOLD`.

Усі дані H117 контрольного виконання та сформовані маніфести зберігаються в приватному native evidence ZIP. Коміт і push runner не виконує.

## Межі достовірності

Це *функціональна реконструкція*, а не відновлення невідомого історичного слова `0360`. Попереднє рішення H117 не поновлювати джерельні пошуки без нових матеріалів зберігається. Машинні слова з першоджерел та реконструйовані елементи окремо позначені через provenance, без повторюваних загальних застережень.
