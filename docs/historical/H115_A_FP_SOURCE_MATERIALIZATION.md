# H115-A — формування розрідженого `.k41` із прийнятої транскрипції H66

**Статус:** `SOURCE_MATERIALIZATION`; числова кваліфікація FP — `OPEN`; фізичний еталон — `NO`.

## Джерельна основа

- В. М. Глушков, Е. Л. Ющенко, *Вычислительная машина «Киев»: математическое описание* (1962), друковані с. 112–117.
- H66: 251 надруковане слово з адресою, полями `opcode a1 a2 a3`, сторінкою, колонкою, рядком скану та текстовим шаром PDF. H65: 13 опорних записів. Виправлено 45 OCR-рядків на підставі зображень сторінок. **Незалежної другої повної людської транскрипції немає**.
- Вхідні архіви H66 залишаються незміненими; їхні SHA-256 жорстко перевіряє `tools/historical/h115_a.py`. Для відтворення достатньо вихідних архівів (або вже закріплених у цьому коміті `.k41` + provenance). `*.k41` — 41-бітові слова, не фізичний образ носія.

Кодування визначено механічно: два восьмеричні розряди opcode та три поля по чотири восьмеричні розряди (14 цифр загалом). Значення 41-бітові; жодне поле (включно з `4000` чи `6314`) не маскується й не перекодовуються. `H114` перевіряє адресний layout, а не семантику всіх виконуваних шляхів.

## Сумісність та обмеження

МП — **альтернативний** комплект змінно-спаяної ПЗП, несумісний з одночасним завантаженням математичного модуля № 1 та блока № 4. Ні `mem/ROM.txt`, ні продукційний CPU, ні початкові дані програми не змінюються. Штатний H114 приймає цей файл **тільки явно** через `--image` і не має неявного source fallback; це збережено свідомо, щоб не розширювати scope H114.

Слова `3574` немає в джерелі; його не слід доповнювати нулем. Пояснення надрукованого твердження про **256 кодів** за наявності **251 адресного запису** — `OPEN_UNRECONCILED`, не твердження про п'ять відсутніх команд. `PASS_SOURCE_MATERIALIZATION_NOT_NATIVE` і `PASS_H114_SOURCE_LAYOUT_NOT_NATIVE` **не означають** ані нативного виконання, ані числового FP PASS, ані апаратного oracle.

## Повторні перевірки (з кореня репозиторію, Git Bash)

```sh
python -B -m unittest discover -s tests/historical -p 'test_h115_a.py' -v && \
python -B tools/historical/h115_a.py \
  --source-zip tempkyiv/kyiv_h115_a_v1/inputs/KYIV_H66_FP_ROM_251_TRANSCRIPTION_V1.zip \
  --evidence-zip tempkyiv/kyiv_h115_a_v1/inputs/H66_FP_ROM_251_WORDS_EVIDENCE_V1.zip \
  --check-k41 examples/historical/gy1962/rom_modules/fp_simulation_251_printed.k41 \
  --check-provenance examples/historical/gy1962/rom_modules/fp_simulation_251_provenance.tsv && \
python -B tools/historical/run.py validate fp_simulation \
  --image examples/historical/gy1962/rom_modules/fp_simulation_251_printed.k41 \
  --sha256 ead80a8af8a207f619647ac1579ff934c6050a55d85a61b92a838ebd3d7662ba
```

## Наступний H115-B

Розібрати історичне подання FP-пар і ABI МП (`3000`, вхід `3300`), незалежно сформувати числові вектори, виконати **обмежені** нативні проби на production CPU з цим альтернативним ROM-set. Зупинятися *до* першого невідомого слова/I/O, і зберегти регресійні порівняння без підгонки або вигаданих слів. Після H115-B скоригувати master `docs/historical/ROADMAP.md` з обов'язковим збереженням незакомічених локальних змін.
