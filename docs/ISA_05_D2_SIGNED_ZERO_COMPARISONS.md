# ISA-05 D2 — знак нуля у командах `04` та `16`

**База:** commit `837032d`; передумова — ISA-05 D1 (`17/17 STRICT`, `3 DOC-MISMATCH`, `2 OBS`). Це вузький патч тільки для `04`/`16`. Кореневий README, ROM, історичний корпус та інші команди не змінюються.

## Джерельні правила

- **GY62**, Глушков—Ющенко (1962), **друкована с. 17**: прямо вказано порядок машинних нулів **`−0 < +0`**. Для `04` перетворення до `int64_t` ототожнює їх і давало хибний перехід для `+0` проти `−0`.
- **GY62**, **друкована с. 13**, абзац **«точное сравнение (Ср3)»**: два числа повинні збігатися **за величиною та знаком**. Тому `16` порівнює 41-бітні машинні слова; `+0` не дорівнює `−0`.
- **Рівність для `04/05` залишається відкритим питанням**: у суцільному тексті GY62 нерівність записано як `<`, у табличному описі — `<=`. Поточну поведінку `<=` D2 зберігає як **POLICY** (а не як доведену історичну семантику). `05` не змінено.

## Реалізація

Для `04` відрізняються лише випадки, коли **обидва модулі нульові, але знаки різні**: `−0` є меншим за `+0`. Решта виконується через попереднє арифметичне `<=`; це мінімізує ризик побічних змін.

Для `16` рівність встановлюється порівнянням повних машинних кодів, обмежених 41-бітною маскою. Це також запобігає впливу випадково записаних позаархітектурних старших бітів `uint64_t` (реакція пам'яті на такий запис не досліджена).

## Тести й критерії прийняття

1. Запустити ISA-05 D1 з `--enforce-doc`: очікуються `STRICT=17/17 DOC-MISMATCH=0 DOC-PASS=3 OBS=2 FAIL=0`.
2. Запустити ISA-05 D2: **17 `STRICT` + 5 `POLICY`**, без `FAIL`.
3. Перезапустити ISA-01–04 та ISA-03 тести (щонайменше основний тест ISA-01). Жодне виправлення поза `04/16` не має бути внесене.
4. Не перетворювати `POLICY` для рівності `04/05` на `STRICT` до документальної звірки.

Усі адреси й коди операцій у тестах наведено у **вісімковій системі**, машинні слова та порівняння — цілочисельні. Архів `tempkyiv/` не комітиться.
