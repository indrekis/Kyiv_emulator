# D15/A3-P3 — reproducible ROM bootstrap in image mode

Parent SHA: `372fc2fc5fe0d5e48fe0087d6e47066f3b7ae8bc` (D15/A3-P2).

The **image** mode starts a real `Kyiv_t` with **no implicit relative-CWD ROM constructor read**, and then explicitly loads a completely preflighted, byte-SHA256-verified ROM image before loading the HOST `.k41` program. SHA pin verification applies to the default ROM and to explicitly pinned custom ROMs; unpinned explicit ROMs are structurally validated and carry their computed digest in the report. This preserves the existing CPU implementation and `kyiv_host_image_v1` parse/run controls. Other legacy CLI modes and the standalone A1 wrapper retain their prior constructor and behavior; no new `--no-rom` normal mode is introduced.

Usage (additive optional arguments to existing `image` syntax):

`kyivemu image FILE.k41 START_OCTAL MAX_STEPS [--allow-rom] [--watch ADDR]... [--rom-file ROM.txt [--rom-sha256 64_HEX_DIGITS]]`

Default ROM resolution uses the **executable directory**, not the process CWD. One of `EXE_DIR/mem/ROM.txt` and `EXE_DIR/../mem/ROM.txt` must exist; two distinct candidates are ambiguous and fail. The default file's SHA-256 is pinned to `a1d9c28e969fa1d74966a78fdbb1bf85b4c45354a764cb8665a73b0a62bdab38`. Thus a normal repo build under `tempkyiv/` picks `repo/mem/ROM.txt`, and a binary in repo root picks `repo/mem/ROM.txt`. A relocated executable must use an appropriate layout or an explicit ROM path; the default never silently starts with no ROM. Explicit `--rom-file` is interpreted relative to the current directory if not absolute; a fully qualified path is recommended for CWD-independent runs. `--rom-sha256` **requires** `--rom-file`, but `--rom-file` does **not** require `--rom-sha256`. The actual SHA-256 of **raw bytes** (including CRLF/LF) is always computed and printed. The default ROM always compares against the pinned checksum. An explicit ROM with `--rom-sha256` also compares against the supplied checksum; without it, the ROM is marked `SHA_PINNED=0` (unpinned) but still undergoes strict structural validation before CPU construction. No network access or shell hashing required.

The accepted ROM text format is exactly four octal address digits plus four octal word groups (`2+4+4+4`), with ASCII horizontal whitespace. Records cover `3010..3277` inclusive, with no duplicates, overwide words, extraneous tokens or non-ASCII characters. Only `3200` may be absent, yielding **183** words. A fully populated explicit file with a `3200` record has **184** words, but that does not constitute independent historical verification. No other missing entries are tolerated; implicit zero is never silently used in place of any other missing cell. The `3000..3007` NK cabinet/panel region is not fabricated in this source. The unprovided `3200` remains machine-initial zero with reported `UNKNOWN_3200=1`, **not** a historically attested zero.

The `.k41` image is validated before the machine is constructed. ROM loading precedes `.k41` image loading; with `--allow-rom`, program words can intentionally overlay ROM and are reported via existing `ROM_OPT_IN=1`. Therefore the pinned ROM hash proves the **base source**, not the final runtime content after an explicit ROM overlay. `D15A3P3-ROM PASS SOURCE=DEFAULT|EXPLICIT WORDS=... UNKNOWN_3200=... SHA256=... SHA_PINNED=0|1` is an additional machine-readable HOST line, while existing `D15A2-LOAD/RUN/WATCH` output remains unchanged. ROM errors have `D15A2-ERROR ROM_*` and exit status 2; no CPU instructions run on preflight failures.

This gate is about execution reproducibility of the **current reconstruction**, not full historical fidelity, NK operator initialization, historical truth of each ROM word, qualification of `3200`, drum geometry, crash durability or a hardware oracle. D15/B1 will transcribe the first 1962 arithmetic diagnostic with exact per-word provenance and separately qualify its initial ROM state and expected terminal cycles.
